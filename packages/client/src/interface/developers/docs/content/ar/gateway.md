# البوابة

البوابة اتصال WebSocket يدفع الأحداث إلى بوتك. أبقِ اتصالًا واحدًا مفتوحًا لكل عملية بوت.

## ما تحتاج إليه {#you-will-need}

يتضمن Node 22 أو أحدث `WebSocket` جاهزًا، ويصلح أي عميل WebSocket آخر. تحتاج إلى رمز بوتك (`YOUR_BOT_TOKEN`).

## الاتصال {#connect}

@@0

| معامل الاستعلام | القيم                                                           | الافتراضي  |
| --------------- | --------------------------------------------------------------- | ---------- |
| `version`       | `1`                                                             | `1`        |
| `format`        | `json` أو `msgpack`                                             | `json`     |
| `token`         | رمز بوتك، بدل `Authenticate`                                    | لا شيء     |
| `intents`       | مجموع نيّات الاتصال، بدل الحقل في `Authenticate`                | انظر أدناه |
| `ready`         | الحقول المطلوبة في `Ready`، مثل `ready=servers&ready=channels`  | كل شيء     |

مع `format=msgpack` يرسل الطرفان إطارات ثنائية.

استخدم `Authenticate` بدل `?token=`، فالعناوين تنتهي في السجلات. أرسله خلال 15 ثانية:

@@1

يجيب السيرفر بهذا الترتيب:

1. `Authenticated`: الرمز صحيح.
2. `Ready`: بياناتك الأولية. لا تبدأ الأحداث إلا بعده.

كل ما ترسله بعد ذلك محدود بـ1 ميبيبايت للرسالة الواحدة.

## حين ترفضك البوابة {#refused}

| ما يصلك                                                              | السبب                                       | ما تفعله                                 |
| -------------------------------------------------------------------- | ------------------------------------------- | ---------------------------------------- |
| `{ "type": "Error", "data": { "type": "InvalidSession" } }` ثم يُغلق الاتصال | رمز خاطئ أو أُعيد تعيينه، أو بوت معلّق، أو لا `Authenticate` خلال 15 ثانية | توقف. لا تُعد الاتصال في حلقة |
| `{ "type": "Error", "data": { "type": "MissingIntent", "intent": "SERVER_MEMBERS" } }` ثم إغلاق بالرمز `4014` | نية خاصة معطلة | فعّلها في بوابة المطورين ثم اتصل مجددًا، أو [اتصل دونها](/developers/docs/gateway#intent-off) |

## إعادة الاتصال {#reconnect}

قد ينتهي الاتصال في أي وقت: تحديث من جهتنا، أو عطل شبكة، أو نوم حاسوبك. خطط لذلك.

1. عند إغلاق المقبس انتظر ثانية واحدة، وضاعف الانتظار بعد كل فشل حتى 30 ثانية. أضف قليلًا من العشوائية كي لا تعود البوتات كلها معًا.
2. اتصل وأرسل `Authenticate` مجددًا. يصلك `Ready` جديد.
3. أعد ضبط الانتظار بعد `Ready`.
4. لا تُعد المحاولة عند `InvalidSession` أو الرمز `4014`: سيفشل الطلب نفسه مجددًا. توقف وأخبر شخصًا.

## الاستئناف غير مدعوم {#resume}

لا يوجد استئناف ولا أرقام تسلسل بعد، وكلاهما مخطط للإصدار القادم (انظر [سجل التغييرات](/developers/docs/changelog)). الأحداث المرسلة في أثناء غيابك ضاعت. بعد كل `Ready` اجلب عبر REST ما لا يجوز أن يفوت بوتك، مثل الرسائل الأخيرة في قناة (`GET /channels/{target}/messages` مع `after` و`sort=Oldest`، انظر [الرسائل](/developers/docs/messages#read-messages)). الأمر المستخدم في أثناء غياب البوت يفشل عند من استخدمه، ويستطيع إعادة المحاولة.

## التجزئة غير مدعومة {#sharding}

يستقبل الاتصال كل ما تغطيه نيّات الاتصال. لا سبيل إلى توزيع السيرفرات بين الاتصالات. لا يمكن بعد تقسيم عملية بوت كبرت كثيرًا، فأبقِ العمل لكل حدث صغيرًا، وانقل العمل البطيء إلى طابور. انظر [التشغيل الفعلي](/developers/docs/production).

يعمل اتصالان بالرمز نفسه، ويستقبل كلاهما كل شيء. عندها يصل `InteractionCreate` إلى الاثنين، فلا تشغّل اتصالين إلا في أثناء إعادة التشغيل.

## نيّات الاتصال {#intents}

تحدد نيّات الاتصال (intents) ما يستقبله الاتصال. تطبقها البوابة، فلا يصل البوت أبدًا ما لم يطلبه. اجمع أرقام النيّات التي تريدها وأرسل المجموع. دون `intents` يحصل البوت على كل النيّات المجانية، أي `63`.

| النية             | القيمة | ما يصلك                                                                  |
| ----------------- | ------ | ------------------------------------------------------------------------ |
| `SERVERS`         | `1`    | أحداث السيرفرات والقنوات والأدوار والرموز التعبيرية والويب هوك، والسيرفرات وقنواتها في `Ready`. تصل الرسائل الخاصة والمجموعات في كل حال، في `Ready` وفي `ChannelCreate` |
| `SERVER_MESSAGES` | `2`    | الرسائل والكتابة في قنوات السيرفرات                                     |
| `DIRECT_MESSAGES` | `4`    | الرسائل والكتابة في الرسائل الخاصة والمجموعات                           |
| `REACTIONS`       | `8`    | إضافة التفاعلات وإزالتها                                                |
| `VOICE_STATES`    | `16`   | دخول الناس القنوات الصوتية وخروجهم، والمكالمات، وحالات الصوت في `Ready` |
| `INTERACTIONS`    | `32`   | `InteractionCreate`                                                      |
| `MESSAGE_CONTENT` | `1024` | خاصة. نص الرسائل وتضميناتها وملفاتها ومكوّناتها                         |
| `SERVER_MEMBERS`  | `2048` | خاصة. انضمام الأعضاء ومغادرتهم وتغيرهم، وقائمة الأعضاء                  |
| `PRESENCE`        | `4096` | خاصة. من المتصل، وحالته                                                 |

البوت الذي يجيب عن الأوامر فقط يحتاج إلى `SERVERS + INTERACTIONS = 33`. دون `INTERACTIONS` لا يسمع بوتك الأوامر.

تُفعَّل النيّات الخاصة للبوت في بوابة المطورين. وطلب نية معطلة يغلق الاتصال بالرمز `4014`. بعد 100 سيرفر لا تبقى إلا النيّات الخاصة التي وافق عليها زرزور: تُستبعد الأخرى من الاتصال دون إغلاقه، وتنطبق قواعد REST أدناه.

القواعد نفسها تسري على REST:

- دون `MESSAGE_CONTENT` تأتي الرسالة بلا نص أو تضمينات أو ملفات أو مكوّنات، إلا إذا كتبها البوت أو ذُكر فيها أو كانت رسالة خاصة معه.
- دون `SERVER_MEMBERS` تجيب قائمة الأعضاء والبحث فيهم بالخطأ `MissingIntent`. يبقى عضو واحد (`GET /servers/{target}/members/{member}`) متاحًا.
- دون `PRESENCE` يظهر كل مستخدم غير متصل، بلا حالة. يرى البوت نفسه كما هو.

يسري تغيير نيّات البوت في اتصاله التالي.

## حين تكون نية خاصة معطلة {#intent-off}

يُحفظ المفتاح في بوابة المطورين لحظة تقلبه، وتؤكد البوابة ذلك. تقرأ البوابة المفاتيح حين يبدأ الاتصال، فيحتفظ الاتصال المفتوح بالنيّات التي بدأ بها: أغلق المقبس واتصل مجددًا. يبقى الرمز كما هو. أما REST فيقرؤها مع كل طلب، فتتبع إجاباته المفتاح فورًا.

يسمّي `MissingIntent` النيّات المعطلة. إذا كان بوتك يعمل دون إحداها، فاتصل مجددًا دونها بدل أن تتوقف:

@@5

دون `MESSAGE_CONTENT` يظل بوتك يقرأ الرسائل التي تذكره، ورسائله هو، والرسائل الخاصة معه. وأضف حلقة إعادة الاتصال من [إعادة الاتصال](/developers/docs/gateway#reconnect) لكل إغلاق آخر.

## مخطط قابل للقراءة آليًا {#schema}

يعيد `GET /gateway/schema` من الواجهة كل حدث (`server`) وكل ما يستطيع العميل إرساله (`client`) في صورة JSON Schema، مع نيّات الاتصال. وهو مولّد من الأنواع التي تستخدمها البوابة.
